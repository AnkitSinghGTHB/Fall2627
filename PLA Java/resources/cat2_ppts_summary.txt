Every character has a weight. The weight of an English uppercase alphabet A-Z is given below. A=1 B=2*A+A C=3*B+B D=4*C+C . . . Y=25*X+X Z=26*Y+Y The weight of any string made up of these characters is the summation of weights of each character. Given a total string weight, determine shortest string of that given weight. If there is more than one solution, return the lexicographically smallest of them. For example, given weight = 25, and the weights of the first few characters of the alphabet are A=1, B=3, C=12, D=60 it is certain that no letter larger than C is required. Some of the strings with a total weight equal to the largest are ABBBBC, ACC, and AAAAAAABBBBBB. The shortest of these is ACC. While any permutation of these characters will have the same weight, this is the lexicographically smallest of them. Function Description Complete the function smallestString in the editor below.

Manacher's Algorithm
What is Manacher's algorithm?
Manacher's algorithm is used to find the longest palindromic substring in any given string. This algorithm is faster than the brute force approach, as it exploits the idea of a palindrome happening inside another palindrome.
Manacher's algorithm is designed to find the palindromic substrings with odd lengths only. To use it for even lengths also, we tweak the input string by inserting the character "#" at the beginning and each alternate position after that (changing "abcaac" to "#a#b#c#a#a#c#").
In the case of an odd length palindrome, the middle character will be a character of the original string, surrounded by "#".

public static void distinctPermutations(String input) {
char[] chars = input.toCharArray();
Arrays.sort(chars);
input = new String(chars);
permute(input.toCharArray(), 0);
}
public static void permute(char[] chars, int index) {
if (index == chars.length - 1) {
System.out.println(String.valueOf(chars));
return;
}
Set<Character> used = new HashSet<>();
for (int i = index; i < chars.length; i++) {
if (used.contains(chars[i]))
continue;
used.add(chars[i]);
swap(chars, index, i);
permute(chars, index + 1);
swap(chars, index, i);
}
}
public static void swap(char[] chars, int i, int j) {
char temp = chars[i];
chars[i] = chars[j];
chars[j] = temp;
}
}

Combination
Permutation and Combination are two important concepts.
Permutation is the different arrangements of the set elements. The arrangements can be made by taking one element at a time, some element at a time and all elements at a time.
Combination is the different selections of the set of elements taken one by one, or some, or all at a time. In Java, the definition of Permutation and Combination is the same.

Josephus trap
In computer science and mathematics, the Josephus Problem (or Josephus permutation) is a theoretical problem.
The problem statement:
There are n people standing in a circle waiting to be executed. The counting out begins at some point in the circle and proceeds around the circle in a fixed direction.
How is the Josephus problem solved?
The Josephus problem can be solved using recursion. For each iteration, recursively delete the Kth position until only one person is left.

N Queens
The N Queen is the problem of placing N chess queens on an N×N chessboard so that no two queens attack each other.
Example
The following is a solution for 4 Queen problem. The expected output is a binary matrix which has 1s for the blocks where queens are placed.
--- Slide 3 ---
What is Backtracking?
In backtracking, we start with one pos­si­ble move out of many avail­able moves. We then try to solve the prob­lem.
What is the N-Queens Problem?
How can N queens be placed on an NxN chessboard so that no two of them attack each other?
This problem is commonly seen for N=4 and N=8.
Let’s look at an example where N=4
N Queens Problem
--- Slide 4 ---
Before solving the problem, you need to know about the movement of the queen in chess.
A queen can move any number of steps in any direction. The only constraint is that it can’t change its direction while it’s moving.
One thing that is clear by looking at the queen’s movement is that no two queens can be in the same row or column.
That allows us to place only one queen in each row and each column.
When N=4, the solution looks like :
N Queens Problem-Movement of Queen
--- Slide 5 ---
Solution to the N-Queens Problem
The way we try to solve this is by placing a queen at a position and trying to rule out the possibility of it being under attack. We place one queen in each row/column.
If we see that the queen is under attack at its chosen position, we try the next position.
If a queen is under attack at all the positions in a row, we backtrack and change the position of the queen placed prior to the current position.
We repeat this process of placing a queen and backtracking until all the N queens are placed successfully.

Topic/Course
Activity Selection Problem
Problem Statement
You are given `n` activities with their start and finish times. Select the maximum number of activities that can be performed by a single person, assuming that a person can only work on a single activity at a time.
Example 1
Input:
`start[] = {2, 4, 3, 7}`
`finish[] = {5, 6, 8, 9}`

public void enqueue(int element) {
if (isFull()) {
System.out.println("Queue is full!");
return;
}
if (front == -1) {
front = 0;  // First element
}
rear = (rear + 1) % size;
queue[rear] = element;

}

public int dequeue() {
if (isEmpty()) {
System.out.println("Queue is empty!");
return -1;
}
int element = queue[front];
if (front == rear) {
front = -1;  // Last element removed
rear = -1;
} else {
front = (front + 1) % size;
}
return element;
}

public int[] maxSlidingWindow(int[] nums, int k) {
int[] result = new int[nums.length - k + 1];
for (int i = 0; i <= nums.length - k; i++) {
int max = nums[i];
// Find max in current window
for (int j = i; j < i + k; j++) {
max = Math.max(max, nums[j]);
}
result[i] = max;
}
return result;  // Time: O(n*k), Space: O(n)
}

Sliding Window Maximum - Algorithm (Deque)
1. Use a Deque to store indices (not values)
2. Maintain indices in decreasing order of their values
3. Remove elements outside current window from front
4. Remove smaller elements from rear before adding new element
5. Add current index to rear
6. The front element is the maximum of current window
Time Complexity: O(n)  | Space Complexity: O(k)

01  |  Introduction to Huffman Coding
"What if shorter codes were assigned to characters that appear more often?"
What?
Huffman Coding is a lossless data compression algorithm invented by David A. Huffman in 1952. It compresses data by assigning shorter binary codes to frequently occurring characters and longer codes to rare ones.
Who invented it?
David Huffman, an MIT student, invented it as a term paper assignment. It became one of the most widely used compression techniques in history.
Key Idea
In standard ASCII, every character takes 8 bits — whether it appears once or a million times. Huffman Coding breaks this rule using variable-length codes.
Result?
Files can be reduced by 20–90% in size, depending on character frequency distribution. This saves storage and speeds up data transfer.
--- Slide 4 ---
Why Huffman? — Fixed vs Variable Length Codes
Character | Frequency | Fixed (3 bits) | Huffman Code | Savings
A | 5 | 000 | 0 | 5×2 = 10 bits saved
B | 4 | 001 | 10 | 4×1 = 4 bits saved
C | 3 | 010 | 110 | 3×0 = 0 bits saved
D | 2 | 011 | 1110 | 2×1 = 2 bits extra
E | 1 | 100 | 1111 | 1×2 = 2 bits extra
🔑  Key Insight: Fixed-length encoding uses 15×3 = 45 bits. Huffman uses only 5×1+4×2+3×3+2×4+1×4 = 36 bits — a 20% reduction on this tiny example alone!
--- Slide 5 ---
02  |  Core Concepts You Must Know
Frequency / Weight
How many times a character appears in the input. Characters with higher frequency get shorter codes.
Priority Queue (Min-Heap)
A data structure that always gives us the element with the LOWEST frequency first. This drives the tree building process.
Binary Tree
A tree where each node has at most 2 children. In Huffman, left = 0 and right = 1. Leaf nodes hold actual characters.
Prefix-Free Codes
No code is a prefix of another code. This ensures unambiguous decoding — we always know when one character ends and the next begins.
Lossless Compression
The original data can be perfectly restored after decompression — no information is lost, unlike lossy formats like JPEG.
Entropy
A measure of information content. Huffman coding approaches the theoretical limit (entropy) of compression for symbol-based data.
--- Slide 6 ---
03  |  The Huffman Algorithm — Step by Step
1
Count Frequencies
Scan the input text. Count how many times each character appears. Store as (character, frequency) pairs.
2
Build Min-Heap
Insert all characters into a Min-Priority Queue (Min-Heap). The character with the lowest frequency has the highest priority.
3
Build the Tree
Repeat until 1 node remains:
• Extract 2 nodes with lowest frequencies
• Create a new parent node with frequency = sum of both
• Insert parent back into the queue
4
Assign Codes
Traverse the tree from root to each leaf:
• Going LEFT adds a '0' to the code
• Going RIGHT adds a '1' to the code
Leaf nodes = actual characters
5
Encode the Data
Replace each character in the original input with its Huffman code. Write the encoded bits to the output file.
6
Decode
Use the same Huffman tree. Read bits one at a time, traverse the tree. When you reach a leaf — that's the character!

05  |  Java — Part 2: Build Tree & Generate Codes
buildTree()  — Greedy Construction
static HuffmanNode buildTree(
PriorityQueue<HuffmanNode> pq) {
// Keep combining until 1 node left
while (pq.size() > 1) {
// Extract 2 smallest nodes
HuffmanNode left  = pq.poll();
HuffmanNode right = pq.poll();
// New parent = sum of both
HuffmanNode parent =
new HuffmanNode('\0',
left.freq + right.freq);
parent.left  = left;
parent.right = right;
pq.add(parent); // re-insert
}
return pq.poll(); // root node
}
generateCodes()  — Tree Traversal
static Map<Character, String> codes
= new HashMap<>();
// Recursively traverse tree
static void generateCodes(
HuffmanNode node, String code) {
if (node == null) return;
// Leaf node = actual character
if (node.left==null && node.right==null) {
codes.put(node.data, code);
System.out.println(node.data
+ " : " + code);
return;
}
// Left child → append '0'
generateCodes(node.left,  code+"0");
// Right child → append '1'
generateCodes(node.right, code+"1");
}

1. Reverse a Linked List
Overview:
• Reverse the direction of all pointers in a linked list
• Convert: 1 → 2 → 3 → 4 → null
To: 4 → 3 → 2 → 1 → null
Two Approaches:
1. Iterative: Using three pointers to reverse links
2. Recursive: Using call stack to reverse in reverse order
Time Complexity: O(n) for both
Space Complexity: O(1) iterative, O(n) recursive (call stack)
--- Slide 3 ---
Reverse LL - Iterative Algorithm
Algorithm Steps:
1. Initialize three pointers:
• prev = null (previous node)
• curr = head (current node)
• next = null (next node)
2. Traverse the linked list:
• Save next node: next = curr.next
• Reverse the link: curr.next = prev
• Move prev to current: prev = curr
• Move curr to next: curr = next
3. Return prev as new head
Example:
Initial: null ← 1 ← 2 ← 3 ← 4 (arrows point backward)
Process each node, reversing pointers one by one
Final: 4 ← 3 ← 2 ← 1, null
--- Slide 4 ---
Reverse LL - Iterative Java Code
class ListNode {
int val;
ListNode next;
ListNode(int val) { this.val = val; }
}
public ListNode reverseListIterative(ListNode head) {
ListNode prev = null;
ListNode curr = head;
while (curr != null) {
// Store next node before reversing
ListNode next = curr.next;
// Reverse the pointer
curr.next = prev;
// Move prev and curr one step
prev = curr;
curr = next;
}
return prev; // new head
}
--- Slide 5 ---
Reverse LL - Recursive Algorithm
Algorithm Steps:
1. Base Case: If head is null or head.next is null, return head
(single node or empty list is already reversed)
2. Recursive Case:
• Recursively reverse the rest of the list
• Store the new head from recursion
• Reverse the pointer from next to current:
curr.next.next = curr
• Set current's next to null: curr.next = null
3. Return the new head
Example:
Reverse(1→2→3→null):
Reverse(2→3→null):
Reverse(3→null):
Reverse(null) = 3 (base case)
Reverse link: 3.next = 2, return 3
Reverse link: 2.next = 1, return 3
3←2←1, null

2. Detect and Remove Loop in LL
Overview:
• A loop occurs when a node's next pointer points to a
previous node in the list (circular reference)
Example:
1 → 2 → 3 → 4 ↓
↑_____↓
Tasks:
1. Detect if a loop exists
2. Find the start node of the loop
3. Remove the loop (break the cycle)
Approach: Floyd's Cycle Detection Algorithm (Tortoise & Hare)
--- Slide 9 ---
Detect Loop - Floyd's Algorithm
Algorithm (Cycle Detection):
1. Initialize two pointers:
• slow = head (moves 1 step at a time)
• fast = head (moves 2 steps at a time)
2. Traverse the list:
• Move slow one step: slow = slow.next
• Move fast two steps: fast = fast.next.next
• If slow == fast, a loop exists
3. Why it works:
In a circular list, fast will eventually catch slow
because fast moves faster in the same circle
Time: O(n) | Space: O(1)
--- Slide 10 ---
Find Loop Start - After Detection
Algorithm (Find Loop Start):
After detecting a loop with slow == fast:
1. Move one pointer to head: slow = head
2. Keep other pointer at meeting point: fast unchanged
3. Move both pointers one step at a time:
• slow = slow.next
• fast = fast.next
4. When slow == fast again, that node is the loop start
Why it works:
• Distance from head to loop start =
Distance from meeting point to loop start
• This mathematical property ensures they meet at start
Time: O(n) | Space: O(1)
--- Slide 11 ---
Detect & Find Loop - Java Code
// Detect if loop exists
public boolean hasLoop(ListNode head) {
if (head == null) return false;
ListNode slow = head;
ListNode fast = head;
while (fast != null && fast.next != null) {
slow = slow.next;
fast = fast.next.next;
if (slow == fast) return true;
}
return false;
}
// Find loop start node
public ListNode findLoopStart(ListNode head) {
if (head == null) return null;
ListNode slow = head;
ListNode fast = head;
// Detect loop
while (fast != null && fast.next != null) {
slow = slow.next;
fast = fast.next.next;
if (slow == fast) break;
}
if (fast == null || fast.next == null)
return null; // No loop
// Find loop start
slow = head;
while (slow != fast) {
slow = slow.next;
fast = fast.next;
}
return slow; // Loop start
}
--- Slide 12 ---
Remove Loop - Java Code
// Remove loop from linked list
public void removeLoop(ListNode head) {
if (head == null) return;
ListNode slow = head;
ListNode fast = head;
// Detect loop
while (fast != null && fast.next != null) {
slow = slow.next;
fast = fast.next.next;
if (slow == fast) break;
}
// No loop found
if (fast == null || fast.next == null) return;
// Find loop start
slow = head;
while (slow.next != fast.next) {
slow = slow.next;
fast = fast.next;
}
// Remove loop by breaking the cycle
fast.next = null;
}
// Complete solution: Detect, Find & Remove
public ListNode removeLoopFull(ListNode head) {
removeLoop(head);
return head;
}

Step 0: slow=1, fast=1

Step 3: slow=4, fast=4  ← COLLISION!
Meeting at node 4. Now find loop start:
Reset slow=1, keep fast=4
Move both one step at a time:
slow=2, fast=5
slow=3, fast=3  ← LOOP START FOUND!
Loop starts at node 3
To remove: Set the node before 3 (which is 5).next = null

3. Merge Two Sorted Linked Lists
Overview:
• Given two sorted linked lists, merge them into one sorted list
• Keep the sorted order intact
Example:
List1: 1 → 3 → 5 → null
List2: 2 → 4 → 6 → null
Result: 1 → 2 → 3 → 4 → 5 → 6 → null
Approach: Two-pointer technique
• Compare nodes from both lists
• Pick the smaller one and advance
• Continue until both lists are exhausted
Time: O(n + m) | Space: O(1) if not counting output
--- Slide 15 ---
Merge Sorted Lists - Algorithm
Algorithm Steps:
1. Create a dummy node to simplify logic
(avoids special case for head)
2. Initialize pointers:
• curr = dummy (to build result list)
• p1 = head1 (pointer to first list)
• p2 = head2 (pointer to second list)
3. Compare and merge:
While both p1 and p2 are not null:
• If p1.val <= p2.val:
- curr.next = p1
- p1 = p1.next
• Else:
- curr.next = p2
- p2 = p2.next
• Move curr forward: curr = curr.next
4. Attach remaining nodes:
• If p1 has remaining: curr.next = p1
• If p2 has remaining: curr.next = p2
5. Return dummy.next (actual head)
--- Slide 16 ---
Merge Sorted Lists - Java Code
public ListNode mergeTwoLists(
ListNode list1, ListNode list2) {
// Create dummy node
ListNode dummy = new ListNode(0);
ListNode curr = dummy;
// Compare and merge
while (list1 != null && list2 != null) {
if (list1.val <= list2.val) {
curr.next = list1;
list1 = list1.next;
} else {
curr.next = list2;
list2 = list2.next;
}
curr = curr.next;
}
// Attach remaining nodes
if (list1 != null) {
curr.next = list1;
} else {
curr.next = list2;
}
return dummy.next;
}
--- Slide 17 ---
Merge Sorted Lists - Complexity
Time Complexity: O(n + m)
• n = length of list1
• m = length of list2
• We visit each node exactly once
• Single pass through both lists
Space Complexity: O(1)
• Only using constant extra space
• Dummy node and three pointers
• Not counting the output list
Example Walkthrough:
list1: 1 → 3 → 5
list2: 2 → 4 → 6
Merge process:
1. 1 ≤ 2 → take 1
2. 3 > 2 → take 2
3. 3 ≤ 4 → take 3
4. 5 > 4 → take 4
5. 5 ≤ 6 → take 5
6. No more in list1 → take 6
Result: 1 → 2 → 3 → 4 → 5 → 6
--- Slide 18 ---
Merge Sorted Lists - Recursive Approach
Recursive Algorithm:
Base Cases:
• If list1 is null, return list2
• If list2 is null, return list1
Recursive Case:
• If list1.val ≤ list2.val:
- list1.next = merge(list1.next, list2)
- Return list1
• Else:
- list2.next = merge(list1, list2.next)
- Return list2
Why it works:
• Recursively find the correct node to pick
• Link it and continue with remaining nodes
• Base cases handle list exhaustion
Time: O(n + m)
Space: O(n + m) due to recursion stack

public ListNode mergeTwoListsRecursive(

1. Valid Parentheses
Overview:
• Determine if a string of parentheses is balanced
• All opening brackets must have matching closing brackets
• Brackets must close in the correct order
Examples:
✓ "()" → Valid
✓ "()[]{}" → Valid
✓ "({[]})" → Valid
✗ "([)]" → Invalid (wrong order)
✗ "([)" → Invalid (missing close)
Approach: Using Stack
• Push opening brackets
• Pop and match closing brackets
• Stack must be empty at end
Time: O(n) | Space: O(n)
--- Slide 3 ---
Balanced Parentheses - Algorithm
Algorithm Steps:
1. Create an empty stack
2. Create mapping of closing → opening brackets:
')' → '('
'}' → '{'
']' → '['
3. Iterate through each character:
• If opening bracket '(', '{', '[':
- Push to stack
• If closing bracket ')', '}', ']':
- If stack is empty, return false (unmatched close)
- Pop from stack
- If popped != expected opening, return false
4. After iteration:
• If stack is empty, return true (valid)
• If stack has elements, return false (unmatched open)
Example: "{[]}"
'{' → push
'[' → push
']' → pop '[', matches ']' ✓
'}' → pop '{', matches '}' ✓
Stack empty → Valid!
--- Slide 4 ---
Balanced Parentheses - Java Code
public boolean isValid(String s) {
Stack<Character> stack = new Stack<>();
// Mapping of closing to opening brackets
Map<Character, Character> map =
new HashMap<>();
map.put(')', '(');
map.put('}', '{');
map.put(']', '[');
for (char c : s.toCharArray()) {
if (c == '(' || c == '{' || c == '[') {
// Opening bracket
stack.push(c);
} else {
// Closing bracket
if (stack.isEmpty()) return false;
char top = stack.pop();
if (top != map.get(c))
return false;
}
}
return stack.isEmpty();
}

2. Next Greater Element
Overview:
• For each element, find the next greater element
• "Next" means to the right in the array
• If no greater element exists, use -1
Example:
Array: [1, 8, 4, 6, 0, 3]
Output: [8, -1, 6, -1, 3, -1]
Explanation:
1 → 8 (next greater)
8 → -1 (no greater element)
4 → 6 (next greater)
6 → -1 (no greater element)
0 → 3 (next greater)
3 → -1 (no greater element)
Naive Approach: O(n²) - check each element
Optimal Approach: Stack - O(n)
--- Slide 8 ---
Next Greater Element - Algorithm (Optimal)
Algorithm Steps (Monotonic Stack):
1. Create result array with -1
2. Create a stack (monotonically decreasing)
3. Traverse array from RIGHT to LEFT:
• While stack not empty AND top < current:
- Pop from stack
- Set result[popped_index] = current
• Push current element to stack
4. Return result array
Why Right to Left?
• When we pop from stack, we push current
• Elements to the right are already processed
• Current element is the next greater for pops
Why Monotonic Stack?
• We maintain decreasing order
• When we find an element > top, it's the answer
• Eliminates redundant comparisons
--- Slide 9 ---
Next Greater Element - Step by Step
Array: [1, 8, 4, 6, 0, 3]
Indices: 0 1 2 3 4 5
Process Right to Left:
Step 1: i=5, val=3
Stack empty, push 5
Stack: [5]
Step 2: i=4, val=0
0 < 3, push 4
Stack: [5, 4]
result[4] = -1
Step 3: i=3, val=6
6 > 0, pop 4, result[4] = 6
6 > 3, pop 5, result[5] = -1
Push 3
Stack: [3]
Step 4: i=2, val=4
4 > 0, but wait... push 2
Process continues...
Result: [8, -1, 6, -1, 6, -1]
--- Slide 10 ---
Next Greater Element - Java Code
public int[] nextGreaterElement(int[] arr) {
int n = arr.length;
int[] result = new int[n];
Stack<Integer> stack = new Stack<>();
// Fill result with -1 initially
Arrays.fill(result, -1);
// Traverse from right to left
for (int i = n - 1; i >= 0; i--) {
// Pop smaller elements
while (!stack.isEmpty() &&
arr[stack.peek()] < arr[i]) {
int idx = stack.pop();
result[idx] = arr[i];
}
// Push current index
stack.push(i);
}
return result;
}
// Alternative: Store elements in stack
public int[] nextGreaterElementV2(int[] arr) {
int n = arr.length;
int[] result = new int[n];
Stack<Integer> stack = new Stack<>();
for (int i = n - 1; i >= 0; i--) {
while (!stack.isEmpty() &&
stack.peek() <= arr[i]) {
stack.pop();
}
result[i] = stack.isEmpty() ? -1 :
stack.peek();
stack.push(arr[i]);
}
return result;
}

3. Min Stack
Overview:
• Design a stack that supports all standard operations
• Additionally, track the minimum element
• All operations should work in O(1) time
Operations:
• push(x): Add element to top
• pop(): Remove and return top element
• top(): Return top element
• getMin(): Return minimum element
Example:
push(5)  → min = 5
push(3)  → min = 3
push(7)  → min = 3
pop()    → removed 7, min = 3
pop()    → removed 3, min = 5
getMin() → returns 5
Constraint: All operations in O(1) time
--- Slide 14 ---
Min Stack - Approach 1: Extra Stack
Algorithm Using Two Stacks:
1. Maintain two stacks:
• mainStack: stores all elements
• minStack: stores minimum at each level
2. push(x):
• Add x to mainStack
• If minStack empty or x <= min:
- Add x to minStack
3. pop():
• Remove from mainStack
• If popped element == minStack top:
- Remove from minStack too
4. top():
• Return mainStack.top()
5. getMin():
• Return minStack.top()
Why It Works:
• minStack always has minimum at each level
• When we pop minimum, minStack pops too
• getMin() always O(1)
Space: O(2n) = O(n)
--- Slide 15 ---
Min Stack - Approach 1: Two Stacks
class MinStack {
private Stack<Integer> mainStack;
private Stack<Integer> minStack;
public MinStack() {
mainStack = new Stack<>();
minStack = new Stack<>();
}
public void push(int val) {
mainStack.push(val);
// Update min stack
if (minStack.isEmpty() ||
val <= minStack.peek()) {
minStack.push(val);
}
}
public void pop() {
int removed = mainStack.pop();
// Update min stack if removed is min
if (removed == minStack.peek()) {
minStack.pop();
}
}
public int top() {
return mainStack.peek();
}
public int getMin() {
return minStack.peek();
}
}

stack;

stack.pop();
}

return stack.peek().first;
}
public int getMin() {
return stack.peek().second;
}
