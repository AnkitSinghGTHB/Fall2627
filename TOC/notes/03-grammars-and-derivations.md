# 📝 Lesson 3 — Grammars & Derivations

> **TL;DR**: A grammar = a set of rules that generates all valid strings of a language. You start from a "start symbol" and keep replacing variables using rules until you have only terminal symbols left. That's a derivation.

---

## 🤔 What is a Grammar?

A grammar is a **recipe** for generating strings in a language. Instead of listing every valid string (impossible for infinite languages), you give **rules**.

Think of it like:
- **English grammar** tells you how to build valid sentences
- **Formal grammar** tells you how to build valid strings

---

## 📋 Formal Definition: G = (V, T, S, P)

| Component | What it is | Example |
|:---:|---|---|
| **V** | Set of **variables** (non-terminals) | {S, A, B} |
| **T** | Set of **terminals** (actual symbols of the language) | {a, b} |
| **S** | **Start symbol** (a special variable, S ∈ V) | S |
| **P** | Set of **production rules** | S → aSb, S → ε |

### The Key Idea:
- **Variables** (uppercase: S, A, B) = placeholders that get replaced
- **Terminals** (lowercase: a, b, 0, 1) = the actual output symbols
- **Productions** = rules saying "replace this with that"

---

## 🔄 Derivation — How Grammars Generate Strings

A **derivation** = the step-by-step process of applying production rules until no variables remain.

### Example: Grammar for L = {aⁿbⁿ : n ≥ 0}

```
G = (V, T, S, P)
V = {S}
T = {a, b}
P = { S → aSb,  S → ε }
```

#### Deriving "aabb":
```
S  →  aSb         (using S → aSb)
   →  aaSbb       (using S → aSb again)
   →  aa ε bb     (using S → ε)
   =  aabb ✅
```

#### Deriving "aaabbb":
```
S  →  aSb  →  aaSbb  →  aaaSbbb  →  aaabbb ✅
```

#### Deriving "ε":
```
S  →  ε ✅
```

> The language: L(G) = {ε, ab, aabb, aaabbb, ...} = {aⁿbⁿ : n ≥ 0}

---

## 🔍 Another Example

```
G = ({A, S}, {a, b}, S, P)
P = { S → aA,  S → b,  A → aa }
```

What strings can this grammar generate?

```
Derivation 1:  S → aA → aaa         → "aaa"
Derivation 2:  S → b                → "b"
```

**L(G) = {b, aaa}** — that's it, just two strings!

## 🏗️ A More Complex Grammar (English-like)

```
sentence    → noun_phrase  predicate
noun_phrase → article  noun
predicate   → verb
article     → "a" | "the"
noun        → "boy" | "dog"
verb        → "runs" | "sleeps"
```

### Derivation of "the boy sleeps":
```
sentence → noun_phrase predicate
         → article noun predicate
         → "the" noun predicate
         → "the" "boy" predicate
         → "the" "boy" verb
         → "the" "boy" "sleeps"  ✅
```

L(G) = {"a boy runs", "a boy sleeps", "the boy runs", "the boy sleeps", "a dog runs", "a dog sleeps", "the dog runs", "the dog sleeps"}

> See? A grammar with ~6 rules generates 8 valid sentences. Now imagine what happens with more rules — you can generate infinite languages!

## 🏛️ The Chomsky Hierarchy (Types of Grammars)

| Type | Name | Production Rule Restriction | Machine |
|:---:|------|---|---|
| **Type 3** | **Regular** | A → aB or A → a (one terminal, optional one variable) | Finite Automaton |
| **Type 2** | **Context-Free** | A → anything (single variable on left side) | Pushdown Automaton |
| **Type 1** | **Context-Sensitive** | |left side| ≤ |right side| | Linear Bounded Automaton |
| **Type 0** | **Unrestricted** | No restrictions | Turing Machine |

```
Type 3 ⊂ Type 2 ⊂ Type 1 ⊂ Type 0

Every regular grammar is also context-free.
Every context-free grammar is also context-sensitive.
And so on.
```

> 🎯 **For Module 1**: You only need **Type 3 (Regular Grammars)** — we'll cover them in detail in Lesson 7.

## 📝 Key Notation to Remember

| Symbol | Meaning |
|:---:|---|
| → | "produces" or "can be replaced by" |
| ⇒ | "directly derives" (one step) |
| ⇒* | "derives" (zero or more steps) |
| \| | "or" (shorthand for multiple rules) |
| ε | empty string |
| L(G) | the language generated by grammar G |

```
S → aS | b    means    S → aS  AND  S → b
                       (two separate rules, written compactly)
```
